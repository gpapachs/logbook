# HACCP Logbook

Εφαρμογή καταγραφής θερμοκρασιών ψυγείων/καταψυκτών **και** πλάνου
καθαρισμού βάσει HACCP, με σύνδεση χρήστη, πίνακα σημερινής κατάστασης,
ιστορικό με εξαγωγή CSV/Excel/PDF, και αυτόματες email υπενθυμίσεις όταν
λείπει καταγραφή. Είναι ένα απλό static site (χωρίς build tools) που
χρησιμοποιεί το [Supabase](https://supabase.com) ως backend (βάση δεδομένων +
σύνδεση χρήστη) και φιλοξενείται δωρεάν στο **GitHub Pages**.

Χρόνος για πρώτη εγκατάσταση: περίπου 15-20 λεπτά.

---

## Βήμα 1 — Δημιουργία project στο Supabase

1. Πήγαινε στο [supabase.com](https://supabase.com) και κάνε εγγραφή/σύνδεση (δωρεάν λογαριασμός).
2. **New project** → δώσε ένα όνομα (π.χ. `fridge-logbook`), διάλεξε κωδικό βάσης
   (κράτα τον κάπου ασφαλές) και περιοχή (π.χ. Central EU).
3. Περίμενε ~1-2 λεπτά μέχρι να είναι έτοιμο το project.

## Βήμα 2 — Δημιουργία πινάκων (SQL)

1. Στο μενού αριστερά: **SQL Editor** → **New query**.
2. Άνοιξε το αρχείο `supabase_schema.sql` από αυτόν τον φάκελο, αντίγραψε όλο
   το περιεχόμενο, επικόλλησέ το στο SQL Editor και πάτα **Run**.
3. Αυτό δημιουργεί τους πίνακες `fridges`, `logs`, `cleaning_tasks` και
   `cleaning_logs`, τους κανόνες ασφαλείας (Row Level Security), δύο
   παραδείγματα ψυγείων και ένα τυπικό πλάνο καθαρισμού HACCP (15 εργασίες) —
   όλα μπορείς να τα αλλάξεις αργότερα μέσα από την εφαρμογή.

## Βήμα 3 — Δημιουργία χρήστη σύνδεσης

Η εφαρμογή είναι μονοχρηστική — φτιάχνεις έναν λογαριασμό για την επιχείρηση.

1. Στο μενού αριστερά: **Authentication** → **Users** → **Add user** → **Create new user**.
2. Βάλε το email και έναν κωδικό. Άφησε το **Auto Confirm User** ενεργό.
3. Αυτά τα στοιχεία (email + κωδικός) θα τα χρησιμοποιείς για να μπαίνεις στην εφαρμογή.

> Θες παραπάνω από έναν χρήστη (π.χ. διαφορετική βάρδια); Πρόσθεσε κι άλλον
> εδώ με τον ίδιο τρόπο — όλοι οι συνδεδεμένοι χρήστες βλέπουν τα ίδια δεδομένα.

## Βήμα 4 — Στοιχεία σύνδεσης (API keys)

1. **Project Settings** (γρανάζι κάτω αριστερά) → **API**.
2. Θα χρειαστείς δύο τιμές:
   - **Project URL** (κάτι σαν `https://xxxxxxxx.supabase.co`)
   - **anon public key** (μεγάλο κλειδί κάτω από "Project API keys")
3. Άνοιξε το αρχείο `config.example.js` από αυτόν τον φάκελο, αποθήκευσέ το ξανά
   ως `config.js` (ίδιος φάκελος) και βάλε τις δύο τιμές:

   ```js
   window.SUPABASE_CONFIG = {
     url: "https://xxxxxxxx.supabase.co",
     anonKey: "eyJhbGciOi...",
   };
   ```

   Το `anon key` δεν είναι μυστικό — είναι σχεδιασμένο να είναι ορατό στον
   κώδικα του browser. Η ασφάλεια των δεδομένων εξασφαλίζεται από τους
   κανόνες RLS που έτρεξες στο Βήμα 2 (μόνο συνδεδεμένος χρήστης βλέπει/γράφει).

## Βήμα 5 — Ανέβασμα στο GitHub

1. Στο [github.com](https://github.com), πάτα **New repository**. Δώσε όνομα
   (π.χ. `fridge-logbook`) και άφησέ το **Public** (χρειάζεται για το δωρεάν
   GitHub Pages, εκτός αν έχεις πληρωμένο πλάνο GitHub).
2. Ανέβασε όλα τα αρχεία αυτού του φακέλου, **συμπεριλαμβανομένου του
   κρυφού φακέλου `.github/`** (περιέχει την αυτόματη υπενθύμιση email —
   βλέπε Βήμα 7). Αν ανεβάζεις με σέρνοντας αρχεία στο GitHub, ο κρυφός
   φάκελος `.github` συνήθως δεν φαίνεται στον Finder/Explorer· γι' αυτό
   είναι προτιμότερο να χρησιμοποιήσεις git από τερματικό, που τον
   συμπεριλαμβάνει αυτόματα:

   ```bash
   cd fridge-logbook
   git init
   git add .
   git commit -m "Πρώτη έκδοση Logbook Θερμοκρασιών"
   git branch -M main
   git remote add origin https://github.com/ΤΟ-USERNAME-ΣΟΥ/fridge-logbook.git
   git push -u origin main
   ```

## Βήμα 6 — Ενεργοποίηση GitHub Pages

1. Στο repo, **Settings** → **Pages** (αριστερό μενού).
2. Στο **Source**, διάλεξε **Deploy from a branch**, branch **main**, φάκελος **/ (root)** → **Save**.
3. Μετά από 1-2 λεπτά, το GitHub θα σου δώσει ένα link σαν:
   `https://ΤΟ-USERNAME-ΣΟΥ.github.io/fridge-logbook/`
4. Αυτό είναι το μόνιμο link της εφαρμογής σου — μπες με το email/κωδικό
   από το Βήμα 3.

## Βήμα 7 — Αυτόματη υπενθύμιση email αν λείπει καταγραφή

Η εφαρμογή απαιτεί μία καταγραφή τη μέρα ανά ψυγείο, και μία καταγραφή ανά
περίοδο (μέρα/εβδομάδα/μήνα) για κάθε εργασία καθαρισμού. Αν περάσει η ώρα
**12:00** χωρίς καταγραφή θερμοκρασίας, ή η ώρα **20:00** χωρίς καταγραφή
καθαρισμού, εμφανίζεται κόκκινη ένδειξη "Δεν καταγράφηκε" στον αντίστοιχο
Πίνακα — αλλά αυτό μόνο του δεν βοηθάει αν κανείς δεν έχει ανοιχτή την
εφαρμογή. Γι' αυτό, το repo έχει **δύο** προγραμματισμένα GitHub Actions
workflows:

- `.github/workflows/daily-log-reminder.yml` — τρέχει στις 12:00 (ώρα
  Ελλάδας), ελέγχει ποια ψυγεία δεν έχουν σημερινή καταγραφή θερμοκρασίας.
- `.github/workflows/daily-cleaning-reminder.yml` — τρέχει στις 20:00 (ώρα
  Ελλάδας), ελέγχει ποιες εργασίες καθαρισμού δεν έχουν καταγραφή για την
  τρέχουσα περίοδό τους (τις ημερήσιες κάθε μέρα, τις εβδομαδιαίες μόνο
  Κυριακή, τις μηνιαίες μόνο την τελευταία μέρα του μήνα).

Και τα δύο καλύπτουν αυτόματα χειμερινή/θερινή ώρα, και αν υπάρχει έστω μία
εκκρεμότητα, στέλνουν email υπενθύμισης. Δεν χρειάζεται καμία επιπλέον
υπηρεσία — χρησιμοποιούν το GitHub (που ήδη έχεις) και ένα Gmail (μπορεί να
είναι το δικό σου) για την αποστολή.

**Χρειάζεται να ορίσεις 5 "secrets" στο repo (κοινά και για τα δύο
workflows)** — **Settings** → **Secrets and variables** → **Actions** →
**New repository secret**, ένα-ένα:

| Secret | Τιμή |
|---|---|
| `SUPABASE_URL` | Το ίδιο URL από το Βήμα 4 (π.χ. `https://xxxxxxxx.supabase.co`) |
| `SUPABASE_SERVICE_ROLE_KEY` | **Project Settings → API → `service_role` secret** (ΟΧΙ το anon key!) |
| `GMAIL_ADDRESS` | Το Gmail από το οποίο θα στέλνονται τα emails |
| `GMAIL_APP_PASSWORD` | "App password" του Gmail (οδηγίες παρακάτω) |
| `NOTIFY_EMAIL` | Το email που θα λαμβάνει την υπενθύμιση (μπορεί να είναι ίδιο με το `GMAIL_ADDRESS`) |

**Πολύ σημαντικό**: το `SUPABASE_SERVICE_ROLE_KEY` παρακάμπτει όλους τους
κανόνες ασφαλείας (RLS) — γι' αυτό μπαίνει **μόνο** εδώ, ως GitHub secret
(κρυμμένο, ποτέ ορατό ούτε σε σένα μετά την αποθήκευση), και ποτέ μέσα σε
αρχείο κώδικα σαν το `config.js`.

**Δημιουργία Gmail App Password:**
1. Στον λογαριασμό Google, ενεργοποίησε **2-Step Verification** αν δεν την
   έχεις ήδη (myaccount.google.com/security).
2. Πήγαινε στο [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords),
   δώσε ένα όνομα (π.χ. "Logbook Ψυγείων") και δημιούργησε το password.
3. Αντίγραψε τον κωδικό (16 χαρακτήρες) — αυτός είναι το `GMAIL_APP_PASSWORD`.

**Δοκιμή**: στο repo, tab **Actions** → επίλεξε ένα από τα δύο workflows
("Υπενθύμιση ημερήσιας καταγραφής θερμοκρασίας" ή "Υπενθύμιση πλάνου
καθαρισμού") → **Run workflow** για χειροκίνητη εκτέλεση εκτός
προγράμματος (χρήσιμο για τεστ — αλλά θα στείλει email μόνο αν η τοπική
ώρα εκείνη τη στιγμή είναι ακριβώς η ώρα-όριο του κάθε workflow, όπως και
το προγραμματισμένο τρέξιμο).

Θες διαφορετική ώρα; Για τα ψυγεία, άλλαξε το `DAILY_DEADLINE_HOUR` στην
αρχή του `app.js` **και** τα δύο `cron:` στο `daily-log-reminder.yml`· για
τον καθαρισμό, το `CLEANING_DAILY_DEADLINE_HOUR` στο `app.js` **και** τα
δύο `cron:` στο `daily-cleaning-reminder.yml`, ώστε να ταιριάζουν (τα
workflows τρέχουν σε UTC· η ελληνική ώρα είναι UTC+2 τον χειμώνα και
UTC+3 το καλοκαίρι).

## Βήμα 8 — Οθόνη "Χρήστες" (προσθήκη/διαγραφή χρηστών μέσα από την εφαρμογή)

Μέχρι εδώ, η προσθήκη νέου χρήστη γινόταν μόνο από το Supabase Dashboard
(Βήμα 3). Η καρτέλα **"Χρήστες"** της εφαρμογής σου επιτρέπει να το κάνεις
κι από μέσα, χωρίς να μπαίνεις στο Supabase. Επειδή η δημιουργία/διαγραφή
χρήστη απαιτεί το `service_role` key (πλήρη πρόσβαση — δεν επιτρέπεται
ποτέ μέσα στον κώδικα του browser), αυτό γίνεται μέσω μιας **Supabase
Edge Function** — μια μικρή server-side συνάρτηση που φιλοξενεί το ίδιο
το Supabase, όπου το κλειδί μένει κρυφό.

**8.1 — Ανάπτυξη (deploy) της συνάρτησης:**

1. Στο Supabase Dashboard, μενού αριστερά: **Edge Functions**.
2. **Deploy a new function** → **Via editor** (γράφεις/επικολλάς τον κώδικα
   κατευθείαν στο πρόγραμμα περιήγησης, χωρίς εγκατάσταση εργαλείων).
3. Όνομα συνάρτησης: `manage-users` (ακριβώς αυτό — έτσι το αναζητά η
   εφαρμογή).
4. Άνοιξε το αρχείο `supabase/functions/manage-users/index.ts` από αυτόν
   τον φάκελο, αντίγραψε όλο το περιεχόμενο και επικόλλησέ το στον editor
   της συνάρτησης, αντικαθιστώντας το προεπιλεγμένο παράδειγμα.
5. **Deploy function**.

> Αν το project σου δεν έχει την επιλογή "Via editor" (παλιότερες εκδόσεις
> Supabase), η εναλλακτική είναι μέσω [Supabase CLI](https://supabase.com/docs/guides/functions/deploy)
> από υπολογιστή: `supabase functions deploy manage-users`.

**8.2 — Ορισμός του διαχειριστή:**

1. Μέσα στη σελίδα της συνάρτησης `manage-users`: tab **Secrets** (ή
   **Settings** → **Edge Functions** → **Secrets**, ανάλογα με την έκδοση).
2. Πρόσθεσε ένα secret: `ADMIN_EMAIL` = το email του δικού σου λογαριασμού
   (αυτού που έφτιαξες στο Βήμα 3) — αυτός ο λογαριασμός θα είναι ο μόνος
   που μπορεί να προσθέτει/διαγράφει χρήστες από την καρτέλα "Χρήστες".
   Κάθε άλλος συνδεδεμένος χρήστης βλέπει την καρτέλα αλλά δεν μπορεί να
   κάνει αλλαγές.

> Τα `SUPABASE_URL`, `SUPABASE_ANON_KEY` και `SUPABASE_SERVICE_ROLE_KEY` τα
> παρέχει αυτόματα το Supabase σε κάθε Edge Function — δεν χρειάζεται να
> τα ορίσεις εσύ ως secrets εδώ.

**8.3 — Χρήση:** μπες στην καρτέλα "Χρήστες" μέσα στην εφαρμογή (με τον
λογαριασμό διαχειριστή). Εκεί βλέπεις τη λίστα χρηστών, με **+ Νέος
χρήστης** για να προσθέσεις κάποιον (email + κωδικός — ενεργός αμέσως,
χωρίς email επιβεβαίωσης) και **Διαγραφή** δίπλα σε κάθε άλλον χρήστη (ο
δικός σου λογαριασμός διαχειριστή δεν μπορεί να διαγραφεί από εδώ, ώστε να
μην κλειδωθείς έξω κατά λάθος). Η διαγραφή αφαιρεί μόνο τη δυνατότητα
σύνδεσης — οι παλιές καταγραφές που έκανε ο χρήστης παραμένουν στο
ιστορικό.

Αν η καρτέλα δείχνει σφάλμα φόρτωσης, ο πιο συνηθισμένος λόγος είναι ότι
λείπει το deploy της συνάρτησης ή το secret `ADMIN_EMAIL` — ξαναδές τα
βήματα 8.1-8.2.

## Πώς λειτουργεί

- **Πίνακας**: κάρτα για κάθε ψυγείο, χρωματισμένη ανάλογα με τη σημερινή
  κατάσταση:
  - 🟢 **πράσινο** — καταγράφηκε σήμερα, εντός ορίων
  - 🔴 **κόκκινο "Εκτός ορίων"** — καταγράφηκε σήμερα, αλλά η τιμή είναι εκτός ορίων
  - 🔴 **κόκκινο "Δεν καταγράφηκε"** — πέρασε η ώρα 12:00 και δεν έχει γίνει
    η υποχρεωτική σημερινή καταγραφή
  - ⚪ **γκρι "Εκκρεμεί"** — δεν έχει καταγραφεί ακόμα σήμερα, αλλά είναι πριν τις 12:00
  Το κουμπί **+ Καταγραφή** ανοίγει φόρμα για νέα μέτρηση· αν η θερμοκρασία
  είναι εκτός ορίων, ζητάει υποχρεωτικά διορθωτική ενέργεια.
- **Αυτόματη email υπενθύμιση** στις 12:00 αν κάποιο ψυγείο δεν έχει
  καταγραφεί — βλέπε Βήμα 7 παραπάνω.
- **Καθαρισμός**: αντίστοιχος πίνακας για το πλάνο καθαρισμού HACCP, χωρισμένος
  σε ομάδες **Καθημερινά / Εβδομαδιαία / Μηνιαία**. Κάθε κάρτα δείχνει την
  κατάσταση της εργασίας για την τρέχουσα περίοδό της:
  - 🟢 **πράσινο "Ολοκληρώθηκε"** — καταγράφηκε ως ολοκληρωμένη μέσα στην περίοδο
  - 🔴 **κόκκινο "Δεν έγινε"** — καταγράφηκε ρητά ως μη ολοκληρωμένη
  - 🔴 **κόκκινο "Δεν καταγράφηκε"** — πέρασε η ώρα-όριο (20:00, την τελευταία
    μέρα της περιόδου για εβδομαδιαίες/μηνιαίες) χωρίς καμία καταγραφή
  - ⚪ **γκρι "Εκκρεμεί"** — δεν έχει καταγραφεί ακόμα, αλλά είναι πριν την ώρα-όριο
  Το κουμπί **+ Καταγραφή** καταχωρεί αν έγινε ή όχι η εργασία και τον υπεύθυνο/η.
- **Αυτόματη email υπενθύμιση** στις 20:00 αν κάποια εργασία καθαρισμού δεν
  έχει καταγραφή για την περίοδό της — βλέπε Βήμα 7 παραπάνω.
- **Ιστορικό**: επιλογή τύπου (Ψυγεία ή Καθαρισμός), με φίλτρα ανά
  ψυγείο/εργασία/ημερομηνία/κατάσταση/συχνότητα και εξαγωγή σε CSV/Excel/PDF
  — ανά ψυγείο ή ανά εργασία (ξεχωριστό φύλλο/σελίδα το καθένα).
- **Ψυγεία**: προσθήκη/επεξεργασία/διαγραφή ψυγείων, serial number και των
  ορίων θερμοκρασίας τους.
- **Πλάνο καθαρισμού**: προσθήκη/επεξεργασία/διαγραφή εργασιών καθαρισμού
  (τι καθαρίζεται, χώρος, συχνότητα). Η εφαρμογή ξεκινά με ένα τυπικό πλάνο
  15 εργασιών για επιχείρηση τροφίμων, που μπορείς να προσαρμόσεις ελεύθερα.
- **Χρήστες**: προσθήκη/διαγραφή χρηστών σύνδεσης μέσα από την εφαρμογή —
  βλέπε Βήμα 8 (χρειάζεται μια εφάπαξ ρύθμιση Edge Function).

## Serial number ψυγείου

Κάθε ψυγείο μπορεί προαιρετικά να έχει serial number (π.χ. αριθμός σειράς
συσκευής). Καταχωρείται στη φόρμα "Νέο/Επεξεργασία ψυγείου", εμφανίζεται στη
λίστα ψυγείων και "φωτογραφίζεται" σε κάθε καταγραφή θερμοκρασίας — αν αλλάξεις
αργότερα το serial ενός ψυγείου, οι παλιές καταγραφές στο ιστορικό κρατάνε το
serial που ίσχυε τη στιγμή της μέτρησης.

## Εξαγωγή ιστορικού

Στην καρτέλα "Ιστορικό" υπάρχουν τρία κουμπιά εξαγωγής: **CSV**, **Excel**
(.xlsx) και **PDF** — όλα εξάγουν ακριβώς τις γραμμές που δείχνουν τα
τρέχοντα φίλτρα.

## Σχετικά με τις αυτόματες καταγραφές (τι δεν υλοποιήθηκε, και γιατί)

Ζητήθηκε η εφαρμογή να καταγράφει αυτόματα μια τιμή "εντός ορίων" στις 12:00
και στις 00:00 όταν δεν έχει μπει χειροκίνητη μέτρηση, χωρίς καμία επισήμανση
ότι πρόκειται για αυτόματη και όχι πραγματική καταγραφή. Αυτό **δεν
υλοποιήθηκε** σκόπιμα: σε ένα logbook που χρησιμοποιείται για έλεγχο
HACCP/ΕΦΕΤ, μια τέτοια καταγραφή θα έμοιαζε με πραγματική μέτρηση. Αν ένα
ψυγείο όντως βγει εκτός ορίων και κανείς δεν το προσέξει/καταγράψει, το
ιστορικό θα έδειχνε ψευδώς "όλα καλά" — κάτι που τόσο ακυρώνει τον σκοπό της
καταγραφής (έγκαιρος εντοπισμός βλάβης) όσο και ισοδυναμεί, σε επιθεώρηση, με
πλαστογράφηση αρχείου ασφάλειας τροφίμων.

Αντ' αυτού υλοποιήθηκε η ασφαλής εναλλακτική: υποχρεωτική καταγραφή 1
φορά/ημέρα με **σαφή κόκκινη ένδειξη "Δεν καταγράφηκε"** (όχι fake τιμή)
όταν περάσει η ώρα των 12:00 χωρίς καταγραφή, και **αυτόματη email
υπενθύμιση** την ίδια ώρα αν λείπει έστω μία μέτρηση — βλέπε Βήμα 7 και
την ενότητα "Πώς λειτουργεί" παραπάνω. Το ιστορικό δείχνει πάντα μόνο
πραγματικές μετρήσεις· ένα κενό παραμένει ορατό ως κενό. Η ίδια λογική
(καμία fake καταγραφή, μόνο σαφής κόκκινη ένδειξη + email υπενθύμιση)
ακολουθείται και στο πλάνο καθαρισμού.

## Ενημέρωση της εφαρμογής αργότερα

Αν θες να αλλάξεις κάτι στον κώδικα στο μέλλον, επεξεργάσου τα αρχεία και
ξανακάνε `git add . && git commit -m "..." && git push` — το GitHub Pages
ενημερώνεται αυτόματα σε λίγα λεπτά.

## Κόστος

Και το Supabase και το GitHub Pages έχουν δωρεάν πλάνο που καλύπτει άνετα
10-15 ψυγεία με έναν χρήστη. Δεν χρειάζεται πιστωτική κάρτα για να ξεκινήσεις.
